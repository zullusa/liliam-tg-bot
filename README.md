# claudetg

Telegram-бот, который передаёт сообщения coding-агенту — Claude Code (`claude -p`)
или OpenCode (`opencode run`) — и присылает ответы в чат.
Получает обновления через long polling (`getUpdates`), ходит в Telegram API через HTTP-прокси.

## Как это работает
- Каждое сообщение запускает агента в streaming JSON-режиме в рабочей директории чата:
  `claude -p --output-format stream-json --resume <session>` или
  `opencode run --format json --session <session>`; текст запроса передаётся через stdin.
- Выбор агента: `CLAUDETG_BACKEND` по умолчанию и `/backend claude|opencode` на каждый чат.
  Сессии у агентов независимые: переключение не сбрасывает историю, каждая продолжится со своей.
- `session_id` сохраняется в `~/.local/state/claudetg/state.json`, поэтому разговор
  продолжается и после перезапуска. Если агент задаёт вопрос, просто ответь сообщением:
  ответ уйдёт в ту же сессию.
- Пока агент работает, бот показывает «печатает…» и (при `SHOW_TOOLS=true`) какие инструменты запускаются.
- Сообщения, пришедшие пока агент работает, встают в очередь и после завершения уходят одним запросом.
- Сообщения от пользователей не из `ALLOWED_USER_IDS` игнорируются.

Команды: `/new`, `/backend [claude|opencode]`, `/cancel`, `/cwd [путь]`, `/status`, `/help`.
Остальные команды со слешем передаются агенту как есть.

## OpenCode
- `opencode run` не умеет добавлять системный промпт флагом, поэтому инструкции бота
  (про Markdown, «не показывай команды», `claudetg send-file`) приклеиваются к началу
  каждого сообщения.
- По умолчанию добавляется `--auto` — автоодобрение разрешений: в неинтерактивном
  запуске без него opencode отклоняет инструменты (аналог permission mode у claude).
  Отключить: `OPENCODE_AUTO=0`.
- Модель всегда передаётся явно: по умолчанию `strata/qwen3.8-flash-next-iq3_s`
  («Qwen3.8-Flash-Next (local)» у Strata). Сменить: `OPENCODE_MODEL=provider/model`,
  `OPENCODE_MODEL=none` — не передавать `-m` и жить по конфигу opencode.
- Агент из конфигурации opencode.json подключается через `OPENCODE_AGENT`.
- `claudetg send-file` работает и из opencode-сессий: переменная `CLAUDETG_CHAT_ID`
  передаётся процессу так же, как процессу claude.
## Лимиты и автoзамещение (claude → opencode → claude)
Когда Claude Code сообщает об исчерпанном лимите (`… limit · resets HH:MM (Europe/Moscow)`),
бот не ждёт сложа руки:

1. Читает JSONL-расшифровку текущей claude-сессии (`~/.claude/projects/**/<session_id>.jsonl`,
   диалог и вызовы инструментов, хвост до 15 000 символов) — если файла нет, использует
   собственный журнал последних обменов чата.
2. Переключает чат на opencode и подклеивает эту расшифровку к первому его сообщению —
   смена начинается сразу, без ожидания сообщения пользователя: бот сам ставит в очередь
   задачу «продолжай работу из контекста, подведи итог и приступай к следующему шагу».
3. В момент сброса лимита (время берётся из сообщения Claude, +1 минута запаса) сам
   возвращается в ту же claude-сессю через `--resume` и добавляет к первому ходу заметку:
   что пользователь просил и что ответил opencode за время смены — claude видит свою
   историю целиком и только дополняется чужими результатами.
4. `/backend claude` — вернуться вручную раньше (автовозврат отменится), `/cancel` — отменить
   автовозврат, оставшись на opencode, `/resume` и `/status` — показать план смены.

Отключить замещение: `CLAUDETG_LIMIT_FALLBACK=0` — тогда прежнее поведение: ждать сброса
и отправить «Продолжай» в ту же claude-сессию. Лимиты у opencode-провайдеров устроены
иначе и автоматически не подхватываются.

## Установка как пользовательской службы
```sh
cargo build --release
install -Dm755 target/release/claudetg ~/.local/bin/claudetg
# конфиг службы не перезаписывай: в нём твой токен и твои id. Если файла ещё нет — скопируй пример,
# а затем обязательно поменяй ALLOWED_USER_IDS: в примере заглушка 123456789, с ней бот молчит
test -e ~/.config/claudetg/claudetg.env || install -Dm600 deploy/claudetg.env.example ~/.config/claudetg/claudetg.env
install -Dm644 deploy/claudetg.service ~/.config/systemd/user/claudetg.service
systemctl --user daemon-reload
systemctl --user enable --now claudetg
loginctl enable-linger $USER   # чтобы служба работала без активного входа в систему
journalctl --user -u claudetg -f
```

Бот запускается и с заглушкой в `ALLOWED_USER_IDS`, но игнорирует все сообщения: в журнале это
выглядит как `ignored message from unauthorized user <id>`. Свой id подскажет @userinfobot, а при
старте служба пишет, какие id ей разрешены.

## Права доступа
`claude -p` не может спросить разрешение интерактивно, поэтому режим задаётся `CLAUDE_PERMISSION_MODE`:
`auto` (по умолчанию) — классификатор сам решает, что безопасно; `bypassPermissions` — без
ограничений (только если доверяешь всем, у кого есть доступ к боту); `acceptEdits` — только правки
файлов, команды shell будут отклонены.

## Отправка файлов

`claudetg send-file [--chat <id>] <путь> [подпись]` присылает файл документом
(до 50 МБ). Бот передаёт процессу claude переменную `CLAUDETG_CHAT_ID`, поэтому
из сессии достаточно указать путь — файл придёт в тот же чат.
